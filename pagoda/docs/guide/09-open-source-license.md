# 09 · 开源协议：pagoda 为什么用 AGPL

## 一句话总结

pagoda 用 AGPL-3.0：任何人都能免费用、随便改，但**谁把 pagoda 的代码拿去做
产品/服务，谁就必须同样开放自己的修改**——包括 SGLang 这样的上游项目。

## 生活化类比

- **Apache-2.0 / MIT**（宽松协议）= 把菜谱贴在公告栏：谁都能拿走，
  连锁餐厅拿去赚钱也不用告诉你，甚至可以稍加改良后宣称是自己的秘方。
- **AGPL-3.0**（强著佐权）= 菜谱可以拿走，但有个约定：你用它开了店，
  你的改良菜谱也必须贴回公告栏。想保密？找作者单独买商业授权。

## 三分钟版 FAQ

**Q：我能公司内部用 pagoda 吗？**
能。内部使用完全自由，不产生任何开放义务。只有"对外分发"或"对外提供网络服务"
才触发 AGPL 义务。

**Q：我能基于 pagoda 写自己的服务吗？**
能，但你的服务如果对外提供，你的修改必须开源。想闭源商用：联系作者买商业授权
（这就是"双协议"模式）。

**Q：SGLang 能把 pagoda 抄走吗？**
不能直接抄代码。SGLang 是 Apache-2.0 项目，并入 AGPL 代码会迫使它整体变更协议——
他们做不到，所以做不到。这就是选 AGPL 的核心原因。

**Q：那 SGLang 看着文档重写一遍怎么办？**
防不住，任何协议都防不住"思想"。所以 pagoda 的护城河是迭代速度、测试/文档资产
和社区，协议只负责堵住"直接搬代码"。

**Q：为什么不用 BUSL（商业源码协议）？**
BUSL 不是 OSI 认证的开源协议；pagoda 希望保持"真开源"身份。BUSL 是合理的备选，
未来如需要可以调整（作者持全部版权时可改协议）。

## 给贡献者的一句话

向 pagoda 提交代码即表示同意：你的贡献以 AGPL-3.0 发布，并授权项目持有者将其
包含在未来的商业授权版本中（这样双协议模式才有可能）。
