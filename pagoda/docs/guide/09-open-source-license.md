# 09 · 开源协议：pagoda 为什么用 Apache-2.0

## 一句话总结

pagoda 使用 Apache-2.0：这是 SGLang、Kubernetes、TensorFlow 等大量基础设施
项目广泛采用的宽松开源协议。任何人都能自由使用、修改、分发，包括商用和闭源，
只需保留版权与许可声明。我们选择它，是为了和 SGLang 所在的开源生态站在同一条
路上，让代码和知识可以双向流动。

## 生活化类比

- **Apache-2.0 / MIT**（宽松协议）= 把菜谱贴出来：谁都能拿走，开餐厅、
  改配方都随意；唯一要求是保留"这个菜谱原本来自这里"的署名。
- **AGPL-3.0**（强著佐权）= 不止要署名，你用它开了店，你的改良菜谱也必须
  贴回来。对想保持最大开放、又不想给使用者添负担的项目，这会显得更重。

pagoda 的目标是"把 SGLang 的架构思想讲清楚、做成一个零依赖的学习参考实现"，
而不是用协议筑墙。因此选择最贴近上游、对使用者最友好的 Apache-2.0。

## 三分钟版 FAQ

**Q：我能在公司项目里用 pagoda 吗？**
能。Apache-2.0 允许商用、闭源、内部使用，不需要额外授权。随分发保留
`LICENSE` 与 `NOTICE` 中的版权和署名即可。

**Q：我能基于 pagoda 改出自己的服务吗？**
能。改完可以闭源发布，只要随分发保留 Apache-2.0 的许可声明与 NOTICE 署名。

**Q：SGLang 上游能复用 pagoda 的代码吗？**
能，这正是我们期待的。pagoda 与 SGLang 同属 Apache-2.0 生态，代码可以双向
流动、互相借鉴；NOTICE 会持续记录这份血缘关系。

**Q：协议这么宽松，会不会被"白嫖"？**
Apache-2.0 的本意就是让软件被最大程度地使用和传播。pagoda 的护城河不在协议
条款，而在清晰的架构文档、测试资产和持续迭代；社区增长带来的可见性，比限制
复用更有价值。

## 给贡献者的一句话

向 pagoda 提交代码即表示同意：你的贡献以 Apache-2.0 发布，版权归你，项目按
同样宽松的条件提供给所有人。
